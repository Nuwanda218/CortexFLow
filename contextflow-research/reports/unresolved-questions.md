# 未解决问题（CF-EXP-001）

按“对第一版架构的影响 × 获取证据的成本”排序。每条注明：缺什么证据、怎么补、需要谁。

## P0（阻塞第一版设计）

### U1. 真实登录态下 ChatGPT 会话 URL 的稳定性
- **缺什么**：`/c/<id>` 在刷新、新标签页、移入/移出项目、重命名后是否保持可解析；项目内会话的规范 URL 是否变化。
- **现有证据**：官方开发者文档以 `conversation_url: https://chatgpt.com/c/123` 返回该形态（官方）；项目 URL 语法仅第三方观察；官方从未承诺 permalink。
- **怎么补**：用户在 Edge 登录 ChatGPT，打开 2 个测试会话 + 1 个测试 Project，扩展只读上报 URL 变化序列（代码已就绪）。
- **需要谁**：用户（授权 + 操作 10 分钟）。

### U2. 真实 ChatGPT DOM 的消息边界、流式完成信号、多模态结构
- **缺什么**：user/assistant 消息的稳定选择器；生成中/完成的可靠信号；代码块/表格/图片/文件的 DOM 结构；虚拟滚动是否导致历史消息不在 DOM 中。
- **现有证据**：仅本地模拟页（L3），真实页面未观察。
- **怎么补**：扩展在真实会话中只上报**结构统计**（元素数量、属性名、文本长度），不读内容；由用户确认后执行。
- **需要谁**：用户（授权 + 15 分钟）。

### U3. 平台规则边界：程序化读取/写入是否被允许
- **缺什么**：OpenAI ToS/Usage Policies 对“浏览器扩展读取页面、填入输入框、用户确认后发送”的具体解释；是否存在官方支持的扩展/集成白名单。
- **现有证据**：ToS（2026-01-01）禁止 "Automatically or programmatically extract data or Output" 与绕过保护措施（官方）；未找到针对浏览器扩展的具体条款。
- **怎么补**：与用户共同阅读条款并做合规判断；必要时只保留“用户手动复制/粘贴 + Core 记录”的最保守形态。
- **需要谁**：用户（决策）。

### U4. 用户 ChatGPT 账号的登录方式（决定 Electron 是否可行）
- **缺什么**：是邮箱/密码登录还是 Google/Microsoft SSO。
- **为什么重要**：Google 官方政策阻断嵌入式 webview 中的 OAuth（`disallowed_useragent`）；若用户用 Google SSO，Electron 路线可能不可行。
- **怎么补**：用户直接告知；无需实验。
- **需要谁**：用户（一句话）。

## P1（影响体验与实现细节）

### U5. Edge 侧边栏作为工作台的实际体验
- **缺什么**：`chrome.sidePanel` 在 Edge 156 中的实际布局、跨标签页保持、与 ChatGPT 页面共存时的可用宽度。
- **现有证据**：manifest 与权限被接受、扩展加载成功；`sidePanel.open()` 需用户手势，自动化未能打开。
- **怎么补**：用户手动加载扩展 → 点击图标 → 打开侧边栏 → 评价。
- **需要谁**：用户（5 分钟）。

### U6. 用户确认式注入的两条路径
- **缺什么**：“填入但不发送”与“填入并发送”在真实 ChatGPT 输入框（contenteditable/ProseMirror 类编辑器）中的可行性与副作用（草稿、快捷键、焦点）。
- **怎么补**：在测试会话中由用户点击确认，扩展执行一次，记录结果。
- **需要谁**：用户（20 分钟）。

### U7. 官方 MCP 路径在用户套餐下的可用性
- **缺什么**：用户套餐类型；能否添加自定义 MCP server；是否需要 Secure MCP Tunnel；工具调用是否可用。
- **现有证据**：完整 MCP 仅 Business/Enterprise/Edu；Pro 仅 read/fetch；Plus 未说明（官方）。
- **怎么补**：用户确认套餐；按官方文档配置一次最小 MCP server（可先用 Tunnel）。
- **需要谁**：用户（确认套餐；如需，1–2 小时配置）。

## P2（技术补全）

### U8. Native Messaging 端到端
- **缺什么**：注册表安装、host manifest、stdio 帧格式、1 MB 上限、SW 生命周期下的重连行为。
- **现有证据**：官方文档（Windows 注册表路径、4 字节长度前缀、1 MB/4 GB 限制）已核查；未实测。
- **怎么补**：写注册表 + host 脚本 + 扩展 `nativeMessaging` 权限，Playwright 驱动 SW 调 `connectNative`。
- **需要谁**：无需用户（约 20 分钟）。

### U9. Core 持久化与多客户端
- **缺什么**：Core 重启后事件恢复、多扩展/多标签页并发、消息去重与幂等。
- **现有证据**：当前实验版为内存存储；重复消息被接受（D-03b）。
- **怎么补**：SQLite + 消息 id + 幂等键；多客户端压测。
- **需要谁**：开发阶段。

### U10. 真实页面 CSP 对 MAIN world 注入的影响
- **缺什么**：chatgpt.com 的 CSP 是否影响 `chrome.scripting.executeScript({world:"MAIN"})`（预期不影响，但未实测）。
- **现有证据**：mock 页上内联 script 被 CSP 拦截、scripting API 正常（L3）。
- **怎么补**：登录态下在真实页面执行一次只读 MAIN world 探测。
- **需要谁**：用户（授权）。

### U11. 本机 Electron 环境风险
- **缺什么**：安全软件（火绒/深信服）对 Electron 的长期影响；打包签名与分发。
- **现有证据**：默认 `%APPDATA%\Electron` 被拒绝访问导致崩溃，改用工作区 userData 后正常（实测）。
- **怎么补**：在目标机器上做安装包冒烟测试。
- **需要谁**：开发阶段。
