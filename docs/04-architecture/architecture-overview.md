# 概念架构概览

阶段：需求与概念设计。组件是**职责划分候选**，不是最终进程边界或技术选型。本轮不确定 Rust、Python、WebSocket、浏览器扩展、桌面容器或数据库。

<a id="arch-responsibilities"></a>
## 1. 核心分工

**全局调度协作者负责智能讨论和建议；ContextFlow Core 负责将已确认任务与实际通信状态确定性地协调起来。**

来源：[S01-A6](../00-audit/material-audit.md#s01-a6)、[S01-B4](../00-audit/material-audit.md#s01-b4)，L969–971；[S01-C4](../00-audit/material-audit.md#s01-c4)，L1273–1303。源稿没有完整 Core 接口规范，以下职责由已讨论行为归纳。

| 概念组件 / 角色 | 主要输入 → 输出 | 职责与边界 | 关联需求 |
| --- | --- | --- | --- |
| ContextFlow 前端 | 工作状态、消息、用户动作 → 展示与控制意图 | 统一消息、协作视图、详情、布局；不将显示草案当执行授权 | FR-01、FR-02、FR-04、FR-11–FR-18、FR-21、FR-22 |
| 全局调度协作者（当前 ChatGPT 网页） | 目标、已有结果、任务状态、Agent 能力 → 自然解释与建议 | 智能协作，不永久绑定某工具；不承担唯一不可干预的执行控制 | FR-01、FR-24 |
| 独立调度意图提取 | 自然回复 → 任务草案 | 将建议转为可审阅结构；不直接执行；自动触发未定 | FR-03 |
| ContextFlow Core | 确认 / 控制意图、工具反馈 → 分发、状态、消息关联 | 候选协调职责；授权、实际状态与传递事实分开 | FR-04、FR-05、FR-15、FR-22、FR-23 |
| ChatGPT 网页适配职责 | 网页交互 / 可观察会话 → 消息读取和允许的结果发送 | 必须先验证能读取什么、向哪发送、如何知道发送结果；不是已存在适配器 | FR-01、FR-07、FR-24 |
| CLI Agent 适配职责 | 已确认任务 → 工具执行 / 反馈 | 映射任务、状态、结果；暂停、终止和权限能力不得假定 | FR-05、FR-06、FR-22、FR-23 |
| 接收策略与待发送队列 | 待回传结果、活动信号、用户选择 → 发送许可 / 暂缓 | 保护当前对话；既不凭模型空闲猜测用户空闲，也不让通知等同于发送 | FR-07–FR-10、FR-18 |
| 工作空间与上下文存储职责 | 消息、任务、结果、结论、关联、布局 → 可回顾的信息 | 隔离项目并保留来源；保存范围与位置未定 | FR-17、FR-19、FR-20 |

这些职责可以在同一模块中实现，也可以拆分；本轮不把每行升级成一个服务或新增一套框架。任务状态管理、消息关联和队列是概念能力，不要求独立守护进程。

<a id="arch-data"></a>
## 2. 核心信息关系

来源：[S01-A4](../00-audit/material-audit.md#s01-a4)、[S01-A5](../00-audit/material-audit.md#s01-a5)、[S01-A7](../00-audit/material-audit.md#s01-a7)。

- 工作空间组织目标、消息、任务流程、会话关联、成果和关键决策。
- 任务包含执行者、描述、上下文、预期输出、限制及当前状态，可关联前置任务与成果。
- 消息包含来源、目标、时间、类型、内容，可关联任务；一项任务可以对应多条消息。
- 执行结果属于具体任务；待回传内容应可追溯到结果与来源任务。
- 流程图、泳道和详情读取同一协作事实，不分别持有独立任务历史。

这不是字段完备的数据库模型。会话关联数量、消息正文保存、草案与已执行任务如何版本化、普通对话是否形成流程节点均未确定。

<a id="arch-assumptions"></a>
## 3. 技术假设与候选，不是决定

| 事项 | 依据 / 假设 | 必须验证或决定的内容 |
| --- | --- | --- |
| ChatGPT 网页消息读写 | 原稿希望正常对话与结果回传 | 接入允许能力、目标会话识别、生成 / 输入状态、送达证据（Q02、Q03、Q06） |
| 自动回传后继续分析 | 场景倾向自动，原文承认需验证 | 发送能否触发期望回复，如何避免打断或重复发送（Q02、Q08） |
| 独立结构化分析 | 历史有明确方案转述；本次背景提额外 LLM API | API 只是候选执行方式；历史未选提供商、模型、schema、触发或成本策略（Q04） |
| CLI 工具任务与状态接口 | 原稿描述 Codex 接收并返回结果 | 支持的运行方式、结果格式、暂停 / 终止能力及限制强制执行（Q08） |
| 完整报告可被访问 | 原稿建议摘要附引用 | ChatGPT 是否能访问引用及如何提供相关内容（Q07） |
| 工作空间可回顾 | 原稿组织消息、成果和决策 | 完整保留策略、可靠性、存储与数据安全（Q07、Q16） |
| 多执行 Agent 并行 | 远期范围和概念分支图 | 是否进入首版、结果组织与确认边界（Q01、Q05、Q09） |

网页适配、CLI 适配、结构化分析都只能描述“需要的能力”，不能在尚未验证时写成可直接调用的既定组件。

<a id="arch-boundaries"></a>
## 4. 当前不引入的复杂机制

材料不足以支持独立多服务系统、通用插件运行时、向量记忆库、自动循环工作流语言、分布式任务队列或跨设备同步。不是永远排除这些技术，而是不在当前需求证据不足时提前承诺。

下一步先明确产品契约（确认、接收、首版闭环），再按必要能力开展技术验证；本轮不开始选型或编码。
