## 先读证据边界

当前目录只有一份历史材料：[需求设计11.3.md](需求设计11.3.md)。它混合了初步设计稿、场景推演和修订建议，没有完整的用户原始发言。文中的「已经确定」「你提出」不能独立证明用户已确认。

因此，**本轮没有将任何历史产品方案标为“用户明确确认”**。本次任务中的项目背景仅作理解线索，不补充为历史决策证据。详见[材料审计](00-audit/material-audit.md)。

## 状态与优先级约定

- **明确要求 / 明确确认**：有可定位的用户原话或批准记录。当前历史材料未提供此类证据。
- **转述待核验**：AI 明确说该内容来自用户要求或认可，但用户原话缺失。不是“已确认”。
- **候选**：AI 提案、示例、推导或无用户批准证据的设计稿条款。
- **未决**：材料显式提问、方案冲突/张力或尚未给出关键边界。
- **技术假设**：希望具备但尚未验证的接入、运行或通信能力。
- **未来扩展**：原稿列在首版之后的方向，不能因为后文画了示意图就提前纳入首版。

优先级沿用原稿的首版意图，并由整理者分为 **P1 核心闭环、P2 支撑体验、扩展**；这不是用户已批准的排序。需求验收标准均为从材料行为提炼的**验收草案**，新增量化阈值一律不代填。

## 维护规则

1. 需求正文只维护在需求层；设计层引用 FR/NFR，不复制完整需求。
2. 新的用户反馈附上原话、日期和来源；只提升被明确确认的条款，不整篇升级。
3. 新决定更新决策记录，并同步受影响的需求、范围与未决问题；保留旧方案和变更理由。
4. 新材料加入审计清单；来源 ID 不复用。当前 S01 分段只是定位同一文件，不是多份独立证据。
5. 涉及未决事项的设计与架构保持条件式描述，不能作为默认实现授权。
6. 对原文件的行号引用以本次审计校验值为基准；后续若材料变动，更新定位记录，而非静默丢失追溯。
