### 一个重要的架构判断

Parser 不应该直接依赖 Bridge，也不应该直接读取浏览器 Session。

原因在于，阶段 A 已经完成了从外部消息到 Core 内部持久化消息的转换。

Parser 的输入应当是 Core 内部的 Message，而不是原始网络请求。

这会带来三个好处：

- Bridge 暂时断开，不影响已接收消息的解析。
- Core 重启后，可以继续处理此前保存的消息。
- 未来即使增加其他消息来源，Parser 也不必重新适配传输协议。

阶段 B 最合理的模块边界是：

```
Message Store → Parser Worker → ParseResult Store
```

| 优先级 | 设计问题                       | 原因                       |
| ------ | ------------------------------ | -------------------------- |
| P0     | 消息状态、原子领取与结果持久化 | 决定是否丢失结果、重复处理 |
| P0     | 崩溃恢复与超时语义             | 决定能否可靠运行           |
| P1     | ParseResult 业务验证           | 决定错误指令是否流入阶段 C |
| P1     | Agent 身份解析                 | 决定能否准确识别目标       |
| P2     | Prompt 优化与复杂语言支持      | 可以在可靠基础上迭代       |

![image-20261107163723071](C:\Users\Nuwanda\AppData\Roaming\Typora\typora-user-images\image-20261107163723071.png)

对于这个例子，成功的结果在逻辑上应该是：

```
ParseResult
  source_message_id: msg_001
  status: parsed
  instructions:
    1. target: Claude Code
       action: 实现 SQLite Message Store

    2. target: Codex
       action: 独立审查数据库事务设计
```

Parser 只负责生成这两条指令，不创建 TaskId，不投递 Agent，也不确认任务执行。

建议区分两个概念。

### 1. 处理状态（Processing State）

表示 Core 当前处理消息的进度。

### 2. 解析结果（ParseResult Status）

表示解析完成后，得到什么业务结论。

两者有关联，但不应混为一谈。

![image-20261107163837000](C:\Users\Nuwanda\AppData\Roaming\Typora\typora-user-images\image-20261107163837000.png)

| 处理状态     | 含义                   | 是否可被普通 Worker 领取 |
| ------------ | ---------------------- | ------------------------ |
| `pending`    | 尚未领取，或等待重试   | 是，满足重试条件时       |
| `processing` | 已被 Worker 领取       | 否，租约有效期间         |
| `parsed`     | 解析成功，结果已保存   | 否                       |
| `unresolved` | 存在无法安全消除的歧义 | 否                       |
| `failed`     | 解析失败，结果已保存   | 否                       |

我建议建立如下处理规则。

| 异常场景               | 建议处理           | 最终 ParseResult  |
| ---------------------- | ------------------ | ----------------- |
| LLM 请求超时           | 有界重试           | 暂不生成          |
| API 返回 429 / 5xx     | 延迟重试           | 暂不生成          |
| LLM 输出 JSON 格式错误 | 有界重试或修复     | 重试耗尽后 failed |
| 指令目标不明确         | 保存歧义原因       | unresolved        |
| Agent 名称无法唯一匹配 | 保存歧义原因       | unresolved        |
| LLM 明确无法解析输入   | 保存失败原因       | failed            |
| Core 在解析中崩溃      | 租约到期后重新领取 | 暂不生成          |
| SQLite 提交失败        | 回滚，不确认完成   | 暂不生成          |
| 旧 Worker 迟到提交     | 拒绝旧领取版本     | 不修改已保存结果  |
