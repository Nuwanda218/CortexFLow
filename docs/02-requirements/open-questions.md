# 未决问题

按对核心闭环与产品边界的影响排序，**不是技术实施排期**。条款中有依据的候选方案与 AI 倾向均注明；材料没有方案的地方明确不补造。确认后同步需求、范围和决策记录。

<a id="q01"></a>
## Q01 多步骤计划如何确认？【高】

- **问题**：一次批准整套计划，还是逐任务批准？修改计划或输入后原批准是否仍有效？
- **已有讨论**：[S01-A6](../00-audit/material-audit.md#s01-a6)，L442 要求所有新任务默认确认；示例只有单任务，没有多步授权边界。
- **候选**：整体 / 逐任务是本次任务要求核查的选项，历史材料未比较；不另拟自动授权方案。
- **状态**：未讨论完整，待用户决策。
- **影响**：FR-04、FR-05、FR-22；建议卡片、依赖执行；D04。解决前不能把“确认一个节点”扩成“批准所有后继”。

<a id="q02"></a>
## Q02 ChatGPT 网页如何接入工作台？【高】

- **问题**：用户实际在哪个输入框交流？怎样读取回复、发送结果及识别目标会话？允许的交互能力和限制是什么？
- **已有讨论**：[S01-A10](../00-audit/material-audit.md#s01-a10)，L602 列为技术验证；[S01-B1](../00-audit/material-audit.md#s01-b1)，L654 描述熟悉的 ChatGPT 输入框；[S01-B3](../00-audit/material-audit.md#s01-b3)，L926 承认自动续答需验证。
- **候选**：历史材料没有明确比较具体接入方案。浏览器扩展、其他网页适配方式等只能作为后续候选，不能认定已选；另用 LLM API 提取意图不等于用 API 替代 ChatGPT 网页会话。
- **状态**：产品交互边界待明确，接入能力待技术验证。
- **影响**：FR-01、FR-03、FR-07、FR-24；几乎全部闭环与 D02、D03、D08。先讨论需要什么能力，不在本轮选技术栈。

<a id="q03"></a>
## Q03 何时允许后台消息进入当前对话？【高】

- **问题**：“没有对话”指模型不生成，还是用户不积极参与？如何保护输入、阅读和思考？
- **已有讨论**：[S01-C1](../00-audit/material-audit.md#s01-c1)，L1053–1077 指出回复结束不等于用户空闲；[S01-C5](../00-audit/material-audit.md#s01-c5) 最后仍询问。
- **候选**：A 模型未生成即可；B 根据交互活动；C 用户开关。AI 倾向 B+C；输入未发送内容、生成中、主动专注是示例规则，不是已确认的充分判据。
- **状态**：明确未决；无法推定已选择 B+C，也不能声称能检测思考。
- **影响**：FR-07–FR-10、FR-18；NFR-03；D08、H02；决定自动化与注意力保护的核心边界。

<a id="q04"></a>
## Q04 调度建议提取何时触发？【高】

- **问题**：每次 ChatGPT 回复后自动提取，还是用户点击提取？调度者能否主动提出建议？
- **已有讨论**：[S01-B1](../00-audit/material-audit.md#s01-b1)，L735–739 问自动或手动，AI 初步倾向自动；[S01-B4](../00-audit/material-audit.md#s01-b4)，L991 再请求评判；[S01-A10](../00-audit/material-audit.md#s01-a10)，L608 倾向主动但控打扰。
- **候选**：自动识别但仅生成草案；手动“提取调度建议”。主动建议是另一边界，不因自动提取就自动获得主动发起权。
- **状态**：未确认。额外 LLM API 的调用时机、成本与信息范围也未定义。
- **影响**：FR-03、FR-24、NFR-03、NFR-05；D03；需防止误提取变成执行授权。

<a id="q05"></a>
## Q05 首版是否执行多 Agent 并行，结果如何组织？【高】

- **问题**：是否仅画并行关系，还是支持多执行 Agent 同时工作？多结果是逐条回传、汇合后再回传，如何突出进展？
- **已有讨论**：[S01-A9](../00-audit/material-audit.md#s01-a9)，L554–555 将一个 CLI Agent 定为首个集成目标、并行为扩展；[S01-A4](../00-audit/material-audit.md#s01-a4)，L239–241 讨论关系展示；[S01-C4](../00-audit/material-audit.md#s01-c4)，L1281–1285 又画出双执行分支；A L606 将关键进展列待设计。
- **候选**：保留原稿首个集成范围；扩大为并行执行。逐条 / 汇合回传是本次核查方向，材料未给详细协议或选择。
- **状态**：范围张力 H01，不能从概念图推断已批准扩版；结果组织未设计。
- **影响**：FR-06–FR-09、FR-12、FR-24、范围与 D11。实际并行未确定前不设计复杂并行调度器。

<a id="q06"></a>
## Q06 工作空间与原生会话怎样关联？【高】

- **问题**：一个工作空间绑定一个还是多个 ChatGPT 会话？切换时是否改变原生会话？已有历史怎样关联？
- **已有讨论**：[S01-A7](../00-audit/material-audit.md#s01-a7)，L479–486 要求工作空间独立并保存 Agent 会话关联；[S01-B3](../00-audit/material-audit.md#s01-b3)，L880 说传回“当前会话”；[S01-C3](../00-audit/material-audit.md#s01-c3)，L1229 只确定布局切换不影响会话的设计意图。
- **候选**：材料未定义关联数量、建立方式或历史导入；一对一 / 多会话只能列为需要选择的关系，不能预设。
- **状态**：产品信息模型未决。
- **影响**：FR-01、FR-07、FR-17、FR-19、FR-20、FR-24；目标会话误投风险、D09。工作空间创建 / 切换操作也未展开。

<a id="q07"></a>
## Q07 展示、保存、回传各保留什么内容？【高】

- **问题**：哪些消息完整保存，哪些只存摘要？日志、源码报告、确认结论的保留期限、位置与删除范围是什么？
- **已有讨论**：[S01-A3](../00-audit/material-audit.md#s01-a3)，L140–144 要求群聊少输出；[S01-A5](../00-audit/material-audit.md#s01-a5) 能查看全文 / 日志；[S01-A7](../00-audit/material-audit.md#s01-a7) 区分信息与相关性；[S01-B3](../00-audit/material-audit.md#s01-b3)，L882 建议摘要加完整报告引用。
- **候选**：摘要 + 完整报告引用是 AI 回传建议；材料没有完整保存政策。不能由“不展示全部”推导为“不保存全部”，也不能由“可看全文”推导为“永久保存”。
- **状态**：内容契约与数据安全待决；凭据与存储保护需求未展开。
- **影响**：FR-06、FR-07、FR-09、FR-14、FR-19、FR-20；NFR-04、NFR-05；D09。

<a id="q08"></a>
## Q08 失败、暂停与取消如何处理？【高】

- **问题**：失败后能否重试、改任务或换 Agent？依赖失败时后续怎么办？运行中暂停 / 取消怎样确认生效？
- **已有讨论**：[S01-A5](../00-audit/material-audit.md#s01-a5)，L380–385 包含错误 / 日志；[S01-A6](../00-audit/material-audit.md#s01-a6)，L438、L450 提出失败后建议、暂停取消；任务状态表没有暂停态。
- **候选**：材料未给恢复策略。本次核查的重试、修改、切换工具只能是待讨论选项，不能默认自动进行。
- **状态**：异常行为与工具控制契约未定义。
- **影响**：FR-05、FR-22、FR-23、NFR-02；确认机制、依赖状态与架构边界。还需定义发送失败与执行失败是否分别呈现。

## Q09 首个完整版本与第一次验证分别覆盖哪些能力？【中高】

- **问题**：原稿范围表之外的队列、上下文、直接指派、四个预设等，哪些必须进入完整首版？最小验证先证明哪条闭环？
- **已有讨论**：[S01-A9](../00-audit/material-audit.md#s01-a9)，L560 区分完整首版与技术原型；[S01-C1](../00-audit/material-audit.md#s01-c1)，L1002 主张队列与焦点控制为正式需求，没有更新完整范围表。
- **候选**：沿原稿完整版本目标、按后段反馈修订；具体取舍未比较。
- **状态**：首版范围待批准，P1/P2 只是整理建议。
- **影响**：全部需求的版本归属；D11、H01，避免将所有候选自动当 MVP 必需。

## Q10 接收模式与专注控制的默认关系？【中高】

- **问题**：三种消息接收模式是否都需要？默认智能是否认可？进入专注对话是否自动静默，退出后是否发送积压内容？
- **已有讨论**：[S01-C1](../00-audit/material-audit.md#s01-c1)，L1065–1077 建议智能 / 手动 / 自动，默认智能；[S01-C4](../00-audit/material-audit.md#s01-c4)，L1237–1258 将静默列为可选并强调与最大化独立。
- **候选**：上述三种模式是 AI 提案，B+C 也未确认；布局与静默独立的方案不等于所有进入 / 退出默认值已定。
- **状态**：候选待用户判断，与 Q03 一起讨论。
- **影响**：FR-08、FR-10、FR-17、FR-18、D10，积压消息可能再次打断用户。

## Q15 队列放在哪里，“删除 / 稍后”具体意味着什么？【中低】

- **已有讨论**：[S01-C1](../00-audit/material-audit.md#s01-c1)，L1079 提出预览、删除、延后、手动发送；[S01-C2](../00-audit/material-audit.md#s01-c2) 建议轻量入口和右侧抽屉，不新增第四栏。

## Q16 怎样衡量收益与质量，最低可靠性是什么？【中】

- **已有讨论**：[S01-A10](../00-audit/material-audit.md#s01-a10)，L609 明列认知负载评估待设计；A §8 只有定性反馈要求。响应时间、容量、恢复行为未给出指标。
- **候选**：材料未给量化方案；操作次数观察和用户反馈只是整理者的验收建议，不能当既定指标。

- **影响**：NFR-01–NFR-07、FR-05、FR-23；决定怎样判断“可用”而非仅“有界面”。
