# 界面与布局设计

主要来源：[S01-A2](../00-audit/material-audit.md#s01-a2)、[S01-A8](../00-audit/material-audit.md#s01-a8)、[S01-C3](../00-audit/material-audit.md#s01-c3)、[S01-C4](../00-audit/material-audit.md#s01-c4)。三栏与自由控制焦点是**转述待核验**，预设与视觉细则是候选。

<a id="ui-panels"></a>
## 1. 三栏的信息职责【FR-16】

| 区域 | 主要职责 | 可见 / 折叠 / 聚焦行为 |
| --- | --- | --- |
| 左栏 | 统一消息与输入，负责交流 | 默认可见；折叠保留恢复入口；专注对话时占据主要空间 |
| 中栏 | 流程图 / 消息泳道，负责理解全局 | 默认可见且原稿建议获得最多空间；详情收起后扩展；可独立聚焦 |
| 右栏 | 当前选中任务 / 消息，负责深入细节 | 默认随选择呈现；可完全收起释放空间；专注执行时扩大阅读空间 |

各区域可调整宽度、折叠或最大化，恢复入口必须可找到；布局状态保存在工作空间。不给定未经讨论的像素宽度、最小窗口尺寸或断点规则。

原稿顶栏示意包含工作空间、Agent 状态与设置，底部示意包含任务状态汇总。它们是信息入口候选，不据此补造复杂设置系统或 Agent 管理页面。

<a id="ui-presets"></a>
## 2. 四种候选预设【FR-17】

| 名称 | 主要区域 | 其他内容 | 不发生的事情 |
| --- | --- | --- | --- |
| 全局协作 | 三栏同时展示，强调总体进展 | 消息、画布、详情并存 | 不新增任务 |
| 专注对话 | 主对话和输入 | 流程与日志可隐藏 | 不停止后台执行；不自动等同于静默 |
| 专注流程 | 可视化画布，可切换流程 / 泳道 | 其他面板可收起 | 不授予画布编辑或执行权限 |
| 专注执行 | 某任务的结果和日志 | 其他面板可收起 | 不更换执行者、不重启任务 |

预设本质是面板可见性和空间分配，不是四套不同业务流程。与静默的可选联动及默认值见 Q10。

<a id="ui-visual"></a>
## 3. 视觉与阅读规则【FR-02、FR-14；NFR-01、NFR-07】

- 整体参考 Codex 桌面版的克制风格，布局灵活性参考 VS Code 的意图由后文转述。
- 中性背景、细边框、适度圆角；非必要不使用阴影和动画，强调色仅服务选中、状态和关键操作。
- 主体用名称与头像识别，状态有文字 / 标识；不要求靠大量颜色记住每个 Agent。
- 中文、英文、代码清晰可读；时间信息弱化，长消息和日志按需展开。
- 重要操作有反馈，正在运行容易识别，重要错误不能隐藏。

材料未提供可读取的原始参考图片，本轮不生成精确视觉稿、配色令牌或组件尺寸。可访问性量化标准也未确认，不把这些规则描述成已通过专项测试。

<a id="ui-canvas"></a>
## 4. 画布与信息密度【FR-11–FR-15】

流程图强调任务状态与依赖；消息泳道强调时间、方向与来源。概览使用短标签，正文与长日志进入详情，避免画布被大量文字占据。

缩放、平移、适应窗口来自原稿交互要求；点击选择也有场景依据。拖拽依赖、图上创建任务未决（Q13）。系统泳道默认隐藏只是候选（Q14），不能丢失其实际传递记录。

<a id="ui-queue"></a>
## 5. 队列与轻量通知【FR-09、FR-10、FR-18】

[S01-C2](../00-audit/material-audit.md#s01-c2) 建议不增加第四栏，使用待处理数量入口和可展开队列。顶部数量、底部完成提示、右侧抽屉都是示例，不能同时认定为三个强制组件。

任务完成标识和待发送数量表达不同信息。用户主动静默时可保留待处理数量，不弹出大型提示、不自动切页；是否仍保留所有错误提示的特殊策略没有定义。

具体队列位置、与详情面板共存方式及取消发送语义见 Q15；消息时机见工作流设计，不由布局规则决定。
