# 工作空间与上下文管理

主要来源：[S01-A7](../00-audit/material-audit.md#s01-a7)、[S01-B2](../00-audit/material-audit.md#s01-b2)、[S01-B3](../00-audit/material-audit.md#s01-b3)。本页是概念信息边界，不选数据库、检索算法或持久化格式。

<a id="ctx-workspace"></a>
## 1. 工作空间【FR-19、FR-17】

材料建议按项目组织主要目标、协作消息、任务流程、Agent 会话关联、成果与关键决策，并保留工作空间布局。

“工作空间独立”不能直接等同于“必定新建一个 ChatGPT 原生会话”。原生会话关联数量、创建方式、切换行为及历史导入未定义（Q06）。布局切换不应改变任务或会话，而工作空间切换的会话行为仍需决定。

<a id="ctx-types"></a>
## 2. 信息种类与证据边界【FR-20；NFR-04】

| 信息种类 | 材料中的用途 | 不能混淆为 |
| --- | --- | --- |
| 原始消息 | 用户与 Agent 交流的来源 | 自动等同于用户已批准的结论 |
| 任务信息 | 描述、执行者、输入、预期结果、限制与依赖 | 普通聊天里一段命令式文字 |
| 执行结果 | 工具实际返回的结果、摘要和成果 | 未完成任务的预测结果 |
| 用户确认的结论 | 已由用户明确确认的信息 | AI 建议、转述或未经验证的推测 |

确认执行某任务与确认其输出结论是两种不同含义。材料没有给出“确认结论”的具体按钮或审批流程，本轮仅保留信息区分，不创造新的交互系统。

执行中的任务可向调度者提供“正在做什么”的已知状态，但不能让其假装拥有尚未返回的源码分析。来源与事实 / 推测的区分在跨 Agent 转发时不能丢失。

<a id="ctx-transfer"></a>
## 3. 传入与回传【FR-07、FR-20、FR-24】

- 执行工具不必获得所有历史，只应获得当前任务相关信息；怎样选择、压缩与审阅上下文尚未设计。
- 调度者需要用户目标、已有结果、当前任务状态与可用 Agent 能力；提供方式受 Q02、Q06 制约。
- 结果回传建议是“结构化摘要 + 完整报告引用 / 访问方式”（S01-B3 L882），属于 AI 候选，不代表已规定统一数据 schema。
- 能“查看完整报告”不等于目标 ChatGPT 会话能够访问本地文件引用；该能力须验证。
- 队列应保留来源任务与时间，让延后处理仍能理解结果为什么出现；发送时机不在本页决定。

<a id="ctx-retention"></a>
## 4. 展示、保存、传递是三个独立边界【FR-02、FR-06、FR-09、FR-14】

| 边界 | 已有讨论 | 未决部分 |
| --- | --- | --- |
| 展示 | 群聊摘要，详情查看完整输出 / 日志 | 哪些进展构成重要消息、默认折叠范围 |
| 保存 | 工作空间拥有消息、流程、成果与决策；要能回顾 | 完整保存 / 只摘要、期限、位置、重启恢复、凭据保护 |
| 传递 | 相关任务信息；结果摘要与报告引用建议 | 必传字段、全文何时发送、多 Agent 汇总、会话可访问性 |
| 取消待发送项 | 原稿“删除 / 延后 / 手动发送” | 是否仅取消发送、保留什么记录；不得推断删除成果 |

Q07 统一管理保存与内容政策；Q15 管理队列操作。没有依据引入向量数据库、共享所有记忆、自动事实抽取、完整审计平台等复杂模块。

概念存储职责只表示应能维护工作空间相关信息，不代表已经决定本地 / 云端、数据库类型或数据迁移方案。
