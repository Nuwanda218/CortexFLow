# 交互设计

本页是候选交互方案，不是用户已批准规格。需求正文见[功能需求](../02-requirements/functional-requirements.md)；布局见[界面设计](ui-design.md)，任务与发送状态见[工作流设计](workflow-design.md)。

<a id="ix-message"></a>
## 1. 统一消息流与输入【FR-01、FR-02、FR-21】

来源：[S01-A3](../00-audit/material-audit.md#s01-a3)。

| 对象 / 状态 | 信息与行为 |
| --- | --- |
| 普通用户输入 | 默认送给全局调度协作者，不广播给所有执行 Agent |
| 显式指定 Agent | 生成面向该 Agent 的待确认草案；不是直接执行命令 |
| 用户消息 / Agent 消息 | 用户靠右、Agent 靠左；以名称与头像识别主体，不依赖大量颜色 |
| 普通调度回复 | 保持自然语言，不强迫回复 JSON |
| 调度建议 | 独立可操作卡片；不是把每句命令式文字变成执行操作 |
| 执行结果 | 以结果摘要卡片显示，提供全文入口；终端输出留在详情 |
| 系统事件 / 人工确认 | 轻量状态提示与简洁确认记录 |
| 异常 | 明确错误提示，不藏在日志最末端 |
| 长正文折叠 / 展开 | 可展开查看；同一 Agent 连续消息可以合并，属可选建议 |

输入未发送内容是原稿建议的消息暂缓信号之一，不能当作完整“空闲检测器”。输入框与 ChatGPT 原生网页的实际关系见 Q02。

## 2. 调度建议卡片【FR-03、FR-04】

来源：[S01-A3](../00-audit/material-audit.md#s01-a3)，L168–189；[S01-B1](../00-audit/material-audit.md#s01-b1)，L691–739。

卡片候选字段：任务内容、执行者、执行模式 / 限制、预期结果。只读扫描示例的限制必须可审阅；不是所有任务都自动设置为只读。原始自然建议与草案需保持可对照关系，落实 FR-03 的审阅要求。

| 卡片状态 / 动作 | 候选行为 | 不可擅自推定 |
| --- | --- | --- |
| 待确认 | 展示将执行的任务；图中可见待确认节点；点击可查详情 | 草案出现不代表自动启动 |
| 修改 | 修改任务内容或执行者，再呈现供确认 | 改动后的任务自动沿用旧批准 |
| 确认 | 记录确认，交由协调系统分发；显示实际执行进展 | 批准单任务等于批准整个后继计划 |
| 拒绝 / 忽略 | 不下发该草案，保留可辨认的操作结果 | 删除原始对话或已完成任务 |

原文“确认执行 / 修改 / 拒绝”与“确认执行 / 编辑 / 忽略”是不同示例用词。这里只统一描述意图，不将“拒绝”和“忽略”的历史记录语义定死。整体计划卡片和逐任务确认仍未决（Q01）。

自动出现还是点击提取，必须在 Q04 确认后决定；这里不把场景中的自动出现当默认值。

## 3. 选中对象与右栏【FR-14、FR-15】

来源：[S01-A5](../00-audit/material-audit.md#s01-a5)、[S01-B2](../00-audit/material-audit.md#s01-b2)。

| 状态 | 展示内容 / 行为 |
| --- | --- |
| 无选中对象 | 原稿说只呈现当前选择相关信息；场景又提到工作空间信息。空白提示 / 工作空间概览尚未统一，不定默认 |
| 选中任务 | 基础信息、原始描述、输入上下文、预期输出、前置任务、进展、错误、结果与后继关系 |
| 选中消息 | 发送者、接收者、时间、类型、正文、关联任务；场景还建议显示传递是否成功 |
| 任务运行 | 可以查看关键进展与日志；不用强迫用户一直展开 |
| 任务完成 | 结果摘要优先；完整输出、成果位置及日志按需查看 |
| 详情折叠 | 释放画布区域，不改变选中任务的执行状态 |

点击消息可定位任务，点击任务可查看关联消息；详情切换不新建另一份历史。场景中“确认后自动展示任务详情”属候选行为，遇到主动静默时不能默认抢焦点。

<a id="ix-control"></a>
## 4. 执行期间的控制【FR-01、FR-22、FR-23】

来源：[S01-A6](../00-audit/material-audit.md#s01-a6)、[S01-B2](../00-audit/material-audit.md#s01-b2)。

用户可继续自然对话、折叠详情、查看进展，任务不因浏览行为暂停。运行未返回时，只能提供当前状态，不能用尚未返回结果作事实分析。

原稿提出暂停 / 取消，但没有工具停止与恢复契约。交互可以表达控制意图，不能提前宣称一定能暂停任意 CLI 工具。失败时展示错误和实际状态；是否重试、切换 Agent、阻塞依赖，统一待 Q08。

<a id="ix-queue"></a>
## 5. 队列预览与注意力控制【FR-08–FR-10、FR-18】

来源：[S01-C1](../00-audit/material-audit.md#s01-c1)、[S01-C2](../00-audit/material-audit.md#s01-c2)、[S01-C4](../00-audit/material-audit.md#s01-c4)。

- 轻量待处理入口让用户知道有新结果，不等于已将结果发入对话。
- 预览可查来源任务、时间、目标和待发送内容；手动发送、延后、取消发送的候选操作见 FR-09。
- 开启静默后任务继续、结果保留、消息先排队，不自动切换页面或弹出大型提示。
- 切换专注布局只改变可见区域；静默控制另行决定。

入口放顶部、底部或右侧抽屉均来自示例，未批准固定位置；抽屉与节点详情如何共存、延后何时恢复、退出静默是否发送积压项见 Q10、Q15。
